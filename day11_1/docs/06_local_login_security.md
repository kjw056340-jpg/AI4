# 로컬 로그인 보안 확인 오류 수정

## 원인

APP_ORIGIN은 `http://127.0.0.1:8000`인데 브라우저에서 `http://localhost:8000`으로 접속하면 Origin 검사가 실패했습니다. 수정 전 같은 요청은 127.0.0.1에서 인증 검사까지 진행하고 localhost에서 HTTP 403으로 차단되는 것을 재현했습니다.

## 수정

로컬 HTTP 개발 환경에서만 같은 포트의 localhost와 127.0.0.1을 함께 허용합니다. APP_ORIGIN이 로컬 주소이고 COOKIE_SECURE=false일 때만 적용합니다.

- 다른 포트나 HTTPS 주소를 임의로 허용하지 않습니다.
- 배포 도메인과 COOKIE_SECURE=true 환경에는 별칭 허용을 적용하지 않습니다.
- CSRF 쿠키·헤더 비교와 cross-site 요청 차단은 계속 적용합니다.

## 검증

관련 자동 테스트를 포함해 43개 테스트를 통과했습니다. 별도 DB 연결 문자열이 필요한 기존 PostgreSQL 테스트 7개는 생략했습니다. 실제 Supabase 장바구니·결제 검증 결과는 [결제 검증 문서](05_payment_verification.md)를 참고하세요.

## 접속

서버를 재시작한 뒤 [로그인 화면](http://127.0.0.1:8000/login)을 새로 열어 로그인하세요. 두 로컬 주소의 쿠키는 별개이므로 한 주소로 로그인했다고 다른 주소에도 로그인되는 것은 아닙니다.
