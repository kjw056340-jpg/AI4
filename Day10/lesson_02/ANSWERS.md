# 실습 후 비교·자기 점검

## 최소 수정

```python
# 변경 전
return limit or 2
# 변경 후
return limit
```

Python에서 숫자 0은 거짓으로 평가된다. `limit or 2`는 limit이 0이면 2를 반환한다.
따라서 SQLite는 LIMIT 0이 아니라 LIMIT 2를 받는다. SQL 문장은 원인이 아니다.
입력을 생략했을 때의 기본값 2는 argparse가 이미 처리하므로 보조 함수가 다시 덮어쓸 필요가 없다.
음수를 거절하는 if와 ValueError는 그대로 둔다.

## 확인 질문 답

1. WHERE는 도시가 같은 행만 남기고 ORDER BY는 남은 행의 순서를 정한다.
2. DESC는 내림차순이다. 점수 95가 80보다 앞선다.
3. 점수가 같으면 id ASC로 작은 id를 먼저 놓아 동점 순서를 분명히 한다.
4. 서울의 점수순 전체 id는 [3, 5, 1, 6], LIMIT 2는 [3, 5]다.
5. LIMIT 0은 0행이다. 입력을 생략한 것과 다르다.
6. 이 수업에서는 음수 입력을 ValueError로 거절한다. SQLite 자체의 음수 LIMIT은 상한 없는 조회를 뜻하므로 수업의 입력 정책과 구분한다.
7. ?는 값 자리표시자다. city와 effective_limit 순서대로 값을 전달한다.
8. 없는 도시의 조회는 오류가 아니라 빈 리스트다.
9. INSERT OR IGNORE는 같은 PK의 행이 이미 있으면 해당 삽입을 건너뛴다.
   기존 값을 갱신하지 않으며 모든 오류를 올바르게 처리하는 일반적 해법도 아니다.
10. 1차시 파일은 nickname까지만 있어 이 차시의 city·points 열이 없다. lesson02.db를 별도로 사용한다.
