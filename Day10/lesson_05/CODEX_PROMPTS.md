# Codex 분석 → 최소 수정 → 검토

실습용 가상 데이터만 사용한다. 실제 개인정보·DB 비밀번호·개인 대화 파일은 프롬프트에 넣지 않는다.
Codex 없이도 같은 질문을 코드와 실행 결과에 대입해 분석할 수 있다.

## 1. 분석

```text
lesson_05의 main.py, check.py, README.md를 읽어줘. solution.py는 아직 읽지 마.
Python 3.12 이상·표준 sqlite3 환경에서 python main.py와 python check.py main으로 재현해줘.
실행은 실제 임시 DB 파일을 사용하고 종료 때 정리해.
기대: 사용자 한 명에게 대화방 두 개, 각 대화방에 메시지 한 개씩 저장되어야 한다.
실제: 사용자 1이 대화방 10과 20을 만들 때 두 번째 INSERT에서 UNIQUE 오류가 나고 준비 작업이 rollback된다.
아직 수정하지 말고 다음 흐름을 추적해줘: ERD의 사용자 1:N 대화방 → conversations.user_id 정의 → 두 번째 대화방 INSERT → UNIQUE 충돌 → rollback
입력·SQL·연결 설정·트랜잭션·새 조회 결과를 코드 위치와 연결해줘.
직접 실행한 사실과 코드에서 확인한 사실·추론을 구분해줘.
```

재현 입력과 기대 결과는 분석의 기준이다. 먼저 수정하지 않으면 원인을 확인하기 전에 데이터나 검사를 바꾸는 일을 줄일 수 있다.

## 2. 최소 수정

```text
main.py에서 확인한 원인을 최소 수정해줘.
보존할 것: 각 표의 id PK·NOT NULL, 사용자 한 명의 여러 메시지, 서로 다른 사용자·같은 표시 이름 허용, 오류 시 rollback.
check.py·solution.py·샘플 데이터·검사 기대값을 바꾸지 마.
거절할 입력을 삭제하거나 결과를 하드코딩하거나 예외를 삼키는 방식으로 우회하지 마.
새 테이블·패키지·다른 차시 기능을 추가하지 마.
python check.py main에서 5개 PASS, failures=0, 종료 코드 0을 확인해줘.
정상 보존과 실패 거절·기존 데이터 보존을 함께 재검사해줘.
실행 불가 항목은 실제 검증하지 못했다고 밝혀줘.
```

보존 조건과 동일 검사는 원래 요구를 만족하는지 확인하기 위한 약속이다. 관련 없는 표·함수 추가를 막으면 변경과 원인의 관계가 분명해진다.

## 3. 검토

```text
수정한 줄과 원인을 연결해서 설명해줘.
python check.py main과 python check.py solution의 실제 출력을 비교해줘.
정상·경계·오류 입력에서 저장·조회·거절·원복이 어떻게 유지됐는지 보여줘.
표·함수·import·변수마다 현재 차시에서 쓰이는지 확인해줘.
의도한 시작 버그 때문에 누락된 조건·설정이 무엇이었는지도 설명해줘.
실행한 환경과 미실행 환경, 검사로 증명하지 못하는 한계를 밝혀줘.
```

코드가 바뀌었다는 설명만으로 끝내지 않고 같은 조건의 실제 결과와 한계를 함께 기록한다.
