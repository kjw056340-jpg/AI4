# 실습 후 비교·자기 점검

## 최소 수정과 원리

```text
user_id INTEGER NOT NULL UNIQUE,
→ user_id INTEGER NOT NULL,
```

conversations의 PK는 대화방 id다. user_id까지 유일하게 만들면 같은 사용자를 참조하는 행이 두 개 존재할 수 없다.

수정 뒤 main·solution의 5개 검사 모두 통과하는지 확인한다.
전체 수정 코드는 solution.py에서 비교한다. 검사 기대값이나 샘플 데이터를 바꾸지 않는다.

## 확인 질문 답

1. **사용자 한 명에 대화방 몇 개가 가능한가?**

   0개 이상이며 여러 개를 허용한다.

2. **대화방의 PK는 user_id인가?**

   아니다. 대화방 자체의 id다.

3. **user_id의 UNIQUE는 어떤 관계를 만드는가?**

   같은 사용자 값의 반복을 막아 사용자당 최대 한 대화방이 된다.

4. **메시지 열을 message1·message2로 만들면?**

   메시지 수가 늘 때 열을 추가해야 하므로 메시지 한 개를 한 행으로 나눈다.

5. **같은 표시 이름 두 명은 가능한가?**

   가능하다. 사용자는 id로 구분한다.

6. **id 값만 맞추면 없는 부모도 DB가 막는가?**

   열 이름·값 자체만으로는 아니다. 실제 참조 무결성은 FK와 활성화 여부를 확인해야 한다.
