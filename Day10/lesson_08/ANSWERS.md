# 실습 후 비교·자기 점검

## 최소 수정과 원리

```text
WHERE c.id = ? ORDER BY m.id, (conversation_id,)
→ WHERE c.id = ? AND c.user_id = ? ORDER BY m.id, (conversation_id, user_id)
```

조회 함수가 user_id 인자를 받아도 실제 SQL에 쓰지 않았다. 저장 경로의 소유 검사로 조회 경로까지 검증된 것은 아니다.

수정 뒤 main·solution의 10개 검사 모두 통과하는지 확인한다.
전체 수정 코드는 solution.py에서 비교한다. 검사 기대값이나 샘플 데이터를 바꾸지 않는다.

## 확인 질문 답

1. **질문 저장 뒤 답변이 거절되면?**

   트랜잭션 전체를 rollback해 질문만 남지 않아야 한다.

2. **저장 때 소유자를 확인하면 조회도 안전한가?**

   아니다. 조회 SQL에서도 조건을 확인해야 한다.

3. **user_id 인자를 받기만 하면 충분한가?**

   실제 SQL과 값 튜플에 사용되는지 확인해야 한다.

4. **빈 답변과 NULL은 같은 규칙인가?**

   공백은 CHECK, NULL은 NOT NULL로 거절한다.

5. **회귀 검사에는 무엇을 담는가?**

   정상 결과·거절 결과·실패 뒤 원래 데이터 보존을 함께 담는다.

6. **이 모듈이 로그인·권한 시스템 전체인가?**

   아니다. user_id는 신뢰 가능한 호출자가 정했다는 전제다. 임의 신원 위조나 파일 직접 읽기를 막는 인증 시스템은 아니다.
