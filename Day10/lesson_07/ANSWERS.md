# 실습 후 비교·자기 점검

## 최소 수정과 원리

```text
COUNT(*) AS message_count
→ COUNT(m.id) AS message_count
```

LEFT JOIN은 자식이 없어도 부모 행을 남긴다. COUNT(*)는 그 행을 세지만 COUNT(m.id)는 NULL 메시지 id를 세지 않는다.

수정 뒤 main·solution의 7개 검사 모두 통과하는지 확인한다.
전체 수정 코드는 solution.py에서 비교한다. 검사 기대값이나 샘플 데이터를 바꾸지 않는다.

## 확인 질문 답

1. **INNER JOIN만 메시지에 적용하면?**

   메시지가 없는 대화방은 목록에서 빠진다.

2. **LEFT JOIN의 부모 행은?**

   자식이 없더라도 남는다.

3. **COUNT(*)와 COUNT(m.id)의 차이는?**

   결합된 행 전체와 NULL이 아닌 메시지 id를 각각 센다.

4. **GROUP BY는 무엇을 기준으로 묶는가?**

   이 실습은 대화방 id와 출력에 쓰는 사용자·제목으로 묶는다.

5. **이력에서 id 순서의 의미는?**

   여기서는 저장된 삽입 순서다. 실제 외부 발화 시각과 같다고 단정하지 않는다.

6. **user_id 필터가 실제 로그인 인증인가?**

   아니다. 전달받은 식별자로 조회 범위만 정한다.
