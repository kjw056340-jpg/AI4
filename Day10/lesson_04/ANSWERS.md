# 실습 후 비교·자기 점검

## 최소 수정과 원리

```text
points INTEGER CHECK(points BETWEEN 0 AND 100)
→ points INTEGER NOT NULL CHECK(points BETWEEN 0 AND 100)
```

CHECK 식이 NULL이면 해당 CHECK만으로 거절하지 않는다. 따라서 필수값 조건은 NOT NULL로 따로 표현해야 한다.

수정 뒤 main·solution의 10개 검사 모두 통과하는지 확인한다.
전체 수정 코드는 solution.py에서 비교한다. 검사 기대값이나 샘플 데이터를 바꾸지 않는다.

## 확인 질문 답

1. **NOT NULL과 CHECK의 차이는?**

   필수값 여부와 값의 조건은 서로 다른 규칙이다.

2. **NULL 점수에 CHECK만 있으면?**

   조건이 NULL이 되므로 해당 CHECK는 거절하지 않는다.

3. **0점은 누락값인가?**

   아니다. 값 0은 허용되는 하한이며 None과 다르다.

4. **같은 이메일은 어떻게 거절하는가?**

   email의 UNIQUE와 NOT NULL 조건으로 검사한다.

5. **INTEGER라고 쓰면 항상 정수만 저장되는가?**

   일반 SQLite 테이블에서는 아니다. 엄격한 정수 전용 검사가 필요한 경우 추가 설계가 필요하다.

6. **오류 뒤 기존 데이터는?**

   현재 삽입을 rollback하고 민지의 기존 행을 유지한다.
