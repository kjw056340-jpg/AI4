# 6차시 테스트 설계표

기대값 근거: GET /profiles/{profile_id}: 1번 응답은 id=1,name=Min 두 필드만 공개합니다. internal_note는 외부 응답에 없어야 합니다. 없는 양수 ID는 404, 잘못된 ID는 422입니다. 200 응답 문서도 ProfileOut 구조여야 합니다. 데이터는 가상입니다.

| ID | 분류 | 입력·순서 | 기대 결과 | 검사 이유 |
| --- | --- | --- | --- | --- |
| L6-N1 | 정상·구조 | GET /profiles/1 | 200; id,name만 존재 | 내부 필드 부재 |
| L6-E1 | 없는 자원 | GET /profiles/99 | 404; detail=Profile not found | 정상 오류 보존 |
| L6-E2 | 입력 오류 | GET /profiles/0 | 422; path.profile_id | 양수 조건 |
| L6-D1 | 문서 | GET 응답 200 schema | ProfileOut 참조; id,name | 문서와 실행 구조 |


이 표는 제작 시 작성·검토한 기준 예시입니다. 학생이 외부 AI를 실제 실행한 대화 기록이 아닙니다. 여러 입력을 /로 표시한 행은 test_api.py에서 각각 별도 입력으로 실행합니다. 상태뿐 아니라 계약에서 중요한 본문·필드·문서·상태 변화를 확인합니다.

## AI 초안 검토 활동

1. CODEX_PROMPTS.md의 생성 프롬프트로 새 표를 요청합니다.
2. 계약에서 기대값을 손으로 계산하고 누락·중복·실행 가능성을 표시합니다.
3. 제공 표와 비교하여 1개 이상 보강 이유를 설명합니다.
4. AI가 만든 test_generated.py를 직접 실행하고 제공 test_api.py도 유지합니다.
5. 통과한 테스트 수만으로 전체 품질을 단정하지 말고 미검증 범위를 적습니다.
