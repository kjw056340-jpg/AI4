# 7차시 테스트 설계표

기대값 근거: POST /tasks: title은 1~20글자이며 201과 id,title을 반환합니다. 두 번 생성한 작업은 다른 양수 ID를 가지고 기존 내용은 보존되어야 합니다. GET /tasks/{task_id}로 읽고 없으면 404, 입력 오류는 422입니다. 삭제·수정은 이번 차시 API에 없습니다.

| ID | 분류 | 입력·순서 | 기대 결과 | 검사 이유 |
| --- | --- | --- | --- | --- |
| L7-N1 | 단일 생성 | title=one / two (각 테스트 새 상태) | 201; 각 id=1 | 격리 준비 |
| L7-S1 | 연속 요청 | read 생성 → write 생성 → 각각 조회 | 서로 다른 양수 ID; 둘 다 원본 보존 | 덮어쓰기 재현 |
| L7-S2 | 중복 제목 | same 생성 두 번 → 각각 조회 | 서로 다른 ID; 각각 존재 | 제목을 ID로 오해 방지 |
| L7-E1 | 조회 오류 | 99 / 0 | 404 / 422 | 없는 자원·형식 구분 |
| L7-E2 | 본문 오류 | {} / 빈 제목 / 21글자 | 422; 저장소 비어 있음 | 실패 상태 불변 |


이 표는 제작 시 작성·검토한 기준 예시입니다. 학생이 외부 AI를 실제 실행한 대화 기록이 아닙니다. 여러 입력을 /로 표시한 행은 test_api.py에서 각각 별도 입력으로 실행합니다. 상태뿐 아니라 계약에서 중요한 본문·필드·문서·상태 변화를 확인합니다.

## AI 초안 검토 활동

1. CODEX_PROMPTS.md의 생성 프롬프트로 새 표를 요청합니다.
2. 계약에서 기대값을 손으로 계산하고 누락·중복·실행 가능성을 표시합니다.
3. 제공 표와 비교하여 1개 이상 보강 이유를 설명합니다.
4. AI가 만든 test_generated.py를 직접 실행하고 제공 test_api.py도 유지합니다.
5. 통과한 테스트 수만으로 전체 품질을 단정하지 말고 미검증 범위를 적습니다.
