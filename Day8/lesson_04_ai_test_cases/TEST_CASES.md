# 4차시 테스트 설계표

기대값 근거: POST /quotes: amount는 엄격한 정수 1~100000원. 10000원 이상이면 1000원 정액 할인, 미만이면 0원 할인입니다. 200 응답은 amount, discount, payable입니다. 입력 오류는 422입니다.

| ID | 분류 | 입력·순서 | 기대 결과 | 검사 이유 |
| --- | --- | --- | --- | --- |
| L4-N1 | 정상 | amount=5000 / 20000 | 200; payable=5000 / 19000 | 초안에도 있는 정상 |
| L4-B1 | 경계 | amount=9999 / 10000 / 10001 | 200; payable=9999 / 9000 / 9001 | 할인 문턱 |
| L4-B2 | 입력 경계 | amount=1 / 100000 | 200; payable=1 / 99000 | 허용 끝값 |
| L4-E1 | 범위·타입·누락 | 0 / 100001 / "10000" / {} | 422; body.amount | 입력 거부 |


이 표는 제작 시 작성·검토한 기준 예시입니다. 학생이 외부 AI를 실제 실행한 대화 기록이 아닙니다. 여러 입력을 /로 표시한 행은 test_api.py에서 각각 별도 입력으로 실행합니다. 상태뿐 아니라 계약에서 중요한 본문·필드·문서·상태 변화를 확인합니다.

## AI 초안 검토 활동

1. CODEX_PROMPTS.md의 생성 프롬프트로 새 표를 요청합니다.
2. 계약에서 기대값을 손으로 계산하고 누락·중복·실행 가능성을 표시합니다.
3. 제공 표와 비교하여 1개 이상 보강 이유를 설명합니다.
4. AI가 만든 test_generated.py를 직접 실행하고 제공 test_api.py도 유지합니다.
5. 통과한 테스트 수만으로 전체 품질을 단정하지 말고 미검증 범위를 적습니다.
예비 비교: `python -m pytest -q test_seed.py`는 시작 코드에서도 통과할 수 있습니다. 이 초안은 5000·20000만 검사하고 정확한 경계 10000을 빠뜨렸습니다. 이어 `python -m pytest -q test_api.py`를 실행하여 차이를 확인합니다.
