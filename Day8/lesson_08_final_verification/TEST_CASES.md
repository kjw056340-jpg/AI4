# 8차시 테스트 설계표

기대값 근거: 전체 정원은 4석입니다. POST /reservations의 name은 1~20글자, seats는 엄격한 정수 1~4입니다. 성공은 201과 id,name,seats,remaining. 남은 좌석 부족은 409와 detail=Not enough seats이며 저장소와 좌석 수를 바꾸지 않습니다. GET /reservations/{reservation_id}는 저장된 예약(id,name,seats)을 200으로, 없으면 404로 반환합니다. 입력 오류는 422입니다. remaining은 생성 당시의 잔여 좌석이며 조회 응답에는 넣지 않습니다.

| ID | 분류 | 입력·순서 | 기대 결과 | 검사 이유 |
| --- | --- | --- | --- | --- |
| L8-N1 | 정상·경계 | 새 상태에서 seats=1 / 4 생성 → 조회 | 201 → 200; remaining=3 / 0 | 생성·조회 구조 |
| L8-S1 | 실패 후 회복 | 3석 승인 → 2석 거절 → 1석 승인 → 조회 | 201 → 409 → 201; 잔여=0; 예약 2개 | 실패 상태 보존 |
| L8-S2 | 실패 후 회복 | 2석 승인 → 3석 거절 → 2석 승인 → 조회 | 201 → 409 → 201; 잔여=0 | 다른 경계 조합 |
| L8-E1 | 입력 오류 | seats=0 / 5 / "1" / true / 누락 | 422; 좌석=4; 예약 없음 | 검증 실패 불변 |
| L8-E2 | 본문 오류 | 빈 이름 / vip 추가 | 422; 저장소 변화 없음 | 필드 정책 |
| L8-E3 | 조회 오류 | 99 / 0 | 404 / 422 | 없음·입력 구분 |
| L8-D1 | 문서 | POST 409 / GET 404 / seats 범위 | 상태 선언; 1~4 범위 | 명세 검증 |


이 표는 제작 시 작성·검토한 기준 예시입니다. 학생이 외부 AI를 실제 실행한 대화 기록이 아닙니다. 여러 입력을 /로 표시한 행은 test_api.py에서 각각 별도 입력으로 실행합니다. 상태뿐 아니라 계약에서 중요한 본문·필드·문서·상태 변화를 확인합니다.

## AI 초안 검토 활동

1. CODEX_PROMPTS.md의 생성 프롬프트로 새 표를 요청합니다.
2. 계약에서 기대값을 손으로 계산하고 누락·중복·실행 가능성을 표시합니다.
3. 제공 표와 비교하여 1개 이상 보강 이유를 설명합니다.
4. AI가 만든 test_generated.py를 직접 실행하고 제공 test_api.py도 유지합니다.
5. 통과한 테스트 수만으로 전체 품질을 단정하지 말고 미검증 범위를 적습니다.
