# 5차시 AI 활동 프롬프트

AI에게는 아래 업무 계약과 현재 차시 파일만 제공합니다. 실제 학습자의 토큰·개인정보·인증 헤더가 있다면 제거합니다. 이번 가상 예제에는 API 키가 없습니다. AI 도구가 실행 기능이 없다면 학생이 명령을 실행하고 결과를 제공합니다.

## 0. 테스트 케이스 생성

```text
FastAPI 5차시를 학습 중이야. README.md의 계약, main.py와 test_api.py를 읽어줘.
README 명령으로 저장한 openapi_snapshot.json이 있으면 함께 읽고 계약과 차이를 표시해줘.
업무 계약: GET /products/{product_id}: 1번 상품은 {id:1,name:tea}. 양의 정수지만 없는 ID는 404와 detail=Product not found, 0 또는 문자 ID는 422입니다. 성공은 200입니다.
로컬·Python 3.12 환경이며 외부 API나 DB는 없어.
현재 구현의 반환값을 정답으로 복사하지 말고 위 계약에서 기대값을 구해줘.
정상·허용 끝값·경계 밖·필수값 누락·타입·이번 차시의 핵심 회귀를 선별해
ID/입력/사전 상태/요청 순서/기대 상태/기대 본문/근거 표를 만들어줘.
해당하지 않는 분류는 억지로 만들지 말고 이유를 적어줘.
표를 먼저 제시하고 각 행을 연결한 pytest 테스트를 test_generated.py에 작성해줘.
TestClient를 사용하고 from main import app으로 시작해줘.
기존 main.py와 제공 test_api.py는 수정하지 마.
생성 테스트가 이번 계약을 지키는지 스스로 검토하고, 실행했다면 실제 명령과 결과를 구분해줘.
```

필요한 이유: 명세에는 모든 업무 규칙이 없으므로 계약을 함께 주며, 테스트의 기대값이 잘못된 구현을 따라가지 않게 합니다. 파일 범위는 다음 차시 기능 혼입을 막습니다. 생성 코드는 신뢰의 근거가 아니라 검토 대상입니다.

## 1. 분석 — 아직 수정하지 않기

```text
[읽을 파일] main.py, test_api.py, README.md, TEST_CASES.md
[환경] Python 3.12. 실제 서버는 python -m uvicorn main:app --host 127.0.0.1 --port 8000 --workers 1
Swagger 주소는 http://127.0.0.1:8000/docs. 자동 테스트는 서버 없이 TestClient 사용.
[재현 명령] python -m pytest -q test_api.py::test_product
[전체 검사] python -m pytest -q test_api.py
[기대] GET /products/{product_id}: 1번 상품은 {id:1,name:tea}. 양의 정수지만 없는 ID는 404와 detail=Product not found, 0 또는 문자 ID는 422입니다. 성공은 200입니다.
[현재 증상] GET /products/99가 404 대신 200과 {id:99,name:unknown}을 반환합니다.
아직 코드를 수정하지 마. 요청 → 입력 검증 → 경로 함수 → 보조 함수/상태 변경 → 응답을 추적해줘.
검증 전에 실행되는 코드와 검증 실패로 실행되지 않는 코드를 구분해줘.
원인 후보를 파일명과 실제 구문으로 설명해줘. 직접 실행한 사실과 추론을 나눠줘.
실행할 수 없으면 실행했다고 쓰지 말고 학생이 확인할 명령을 적어줘.
```

필요한 이유: 기대와 실제를 함께 주면 증상을 임의의 정책 변경으로 해결하는 일을 줄입니다. 호출 추적은 원인이 경로 함수 밖에 있거나 실행 순서에 있을 수 있음을 확인하게 합니다.

## 2. 최소 수정

```text
확인한 원인을 main.py 안에서 최소 수정해줘.
[보존] GET /products/{product_id}: 1번 상품은 {id:1,name:tea}. 양의 정수지만 없는 ID는 404와 detail=Product not found, 0 또는 문자 ID는 422입니다. 성공은 200입니다.
[제약] requirements.txt 패키지 유지, 새 API·파일·서버·DB·다음 차시 기능 추가 금지.
테스트를 삭제하거나 skip/xfail로 숨기거나, 잘못된 구현에 기대값을 맞추지 마.
하드코딩으로 특정 테스트 입력만 통과시키지 말고 원인을 수정해줘.
[완료] python -m pytest -q test_api.py 전체 통과와 같은 입력의 실제 응답 확인.
test_generated.py를 만들었다면 함께 실행하되 계약과 충돌하는 기대값은 먼저 검토해줘.
수정 전후 diff, 실행 명령, 실제 결과를 제시해줘. 실행 제한은 명확히 밝혀줘.
```

필요한 이유: 정상 기능과 계약을 고정해야 수정으로 생긴 새 오류를 찾을 수 있습니다. 완료 기준은 AI의 설명 대신 재실행 결과로 판단하게 합니다.

## 3. 검토

```text
현재 main.py의 변경 부분을 원인과 연결해 설명해줘.
정상·의도한 실패 처리·핵심 회귀를 어떻게 재검증했는지 실제 명령과 결과를 보여줘.
등록된 모든 학습 경로가 현재 테스트나 Swagger 활동에서 실제 호출되는지 확인해줘.
미사용 import·변수·정의·의존성, 다른 차시 기능이 추가되지 않았는지 확인해줘.
AI가 만든 테스트의 기대값 근거와 누락 가능성을 검토해줘.
실제로 실행한 검증과 미검증 한계를 구분해줘. 테스트 통과를 모든 버그의 부재라고 말하지 마.
```

필요한 이유: 수정의 효과와 새 코드의 필요성을 설명할 수 있어야 합니다. 문법·테스트 통과만으로 수업 범위나 모든 운영 조건까지 검증된 것은 아닙니다.
