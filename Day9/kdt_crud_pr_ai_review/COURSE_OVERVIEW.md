# 8차시 강의 설계: CRUD 통합 서비스 + GitHub PR 협업 + AI 코드 리뷰

**대상:** 파이썬과 FastAPI의 기초, Git의 add/commit 경험이 있는 비전공자. **총 8×50분=400분.** 별도 환경 설정 시간과 선택 심화는 포함하지 않음.

**최종 산출물:** 간단한 할 일(Task) CRUD 서비스 + API 검증 기록 + GitHub PR + 리뷰 반영 이력. GitHub 협업은 실계정과 인터넷이 필요하지만 1차시 핵심 API 검증은 오프라인 로컬에서 가능.

| 차시 | 핵심 질문·범위 | 50분 활동 | 산출물 |
| --- | --- | --- | --- |
| 1 | 조회와 등록이 공유하는 상태에 버그가 생기면? GET/POST 통합 | 호출 추적, ID 중복 재현·수정 | GET/POST 실행·검사 로그 |
| 2 | 개별 항목을 찾지 못하면? GET `/tasks/{id}` 와 404 | 조회 함수·경계값·AI 테스트 | 개별 조회 검사 |
| 3 | 전체 수정과 부분 수정 차이는? PUT/PATCH | Pydantic 모델·수정 반영 검증 | 수정 API와 테스트 |
| 4 | 삭제 후 일관성은? DELETE 및 CRUD 통합 | 상태 변경·삭제·전체 흐름 검사 | 4종 CRUD 통합본 |
| 5 | 협업 시작은 어떻게? Git branch/commit/push | 역할 분담·기능 브랜치·diff 확인 | 기능 브랜치와 커밋 |
| 6 | PR은 왜 필요한가? GitHub PR 생성 | PR 본문·테스트 근거·리뷰 요청 | 리뷰 가능한 PR |
| 7 | AI가 리뷰한 코드를 믿어도 될까? | AI 리뷰→재현→코멘트/수정→재검증 | 코드 리뷰·수정 커밋 |
| 8 | 언제 병합해도 되는가? | 리뷰 확인·충돌 시나리오·병합·회고 | 병합 기록·최종 시연 |

학습 순서: 1–4차시에서 CRUD 안정화 → 5–8차시에서 그 변경을 PR로 협업. 차시별 실습 코드는 독립 실행 가능하도록 각 시간에 실제 호출하는 경로만 포함한다. 인증·DB·CI 등은 기본 범위 밖이다.
