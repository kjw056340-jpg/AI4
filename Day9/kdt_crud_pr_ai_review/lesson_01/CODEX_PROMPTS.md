# Codex 사용 활동 — 순서대로 입력

## 1. 분석 (지금은 수정 금지)

```text
lesson_01/main.py와 check.py만 읽어줘. FastAPI 앱은 단일 worker로 실행하며
python check.py main 결과는 GET 200, POST 201이지만 ID 목록 [1,3,3]에서 실패한다.
기대값은 [1,3,4]이다. GET/POST 호출 → next_id() → 리스트 수정 흐름을 추적해줘.
코드는 아직 수정하지 말고 원인 후보와 근거 줄을 보여줘.
직접 실행으로 확인한 사실과 추론을 구분하고 개인정보/토큰은 출력하지 마.
```

왜? 실패한 요청과 실제·기대를 명시해야 AI가 다른 기능을 임의로 바꾸지 않음.

## 2. 최소 수정

```text
확인한 ID 중복 원인만 main.py에서 최소 수정해줘.
GET /tasks 응답과 POST /tasks 요청/응답 구조, 상태 코드 200/201, 초기 ID [1,3]은 유지해.
새 라이브러리, 새 API, DB, 다른 차시 기능, 테스트 우회는 금지.
python check.py main으로 GET 조회와 ID 4 생성 성공을 실제 검증해.
실행하지 못했다면 그 사실을 명시해.
```

왜? 정상 기능 보존과 변경 범위를 고정해야 회귀 오류를 줄일 수 있음.

## 3. AI 코드 리뷰

```text
main.py 변경 전후를 비교해줘. 어떤 수정 줄이 중복 ID 원인을 해결했는지 설명해줘.
GET 200·POST 201·새 ID 4 검증 결과와 실행 명령을 보여줘.
미사용 import, 무의미한 코드, 다른 차시용 함수나 API가 생겼는지 확인해줘.
메모리 저장 방식의 한계와 검증하지 않은 조건을 구분해 적어줘.
```

왜? AI 리뷰도 실제 검사 근거를 확인해야 하며, 지적 사항을 무조건 수용하지 않기 위함.
