# Codex 활동 3단계 — 2차시

**1. 분석 (수정 금지)**

```text
읽을 파일: main.py, check.py, CODE_GUIDE.md.
실행 조건: lesson_02 폴더에서 python check.py main 실행.
기대: 기존 /tasks/1 → 200; 미존재 /tasks/999 → 학생 200 null, 정답 404
관찰 목표: 없는 항목에 None을 그대로 반환해 200 null이 된다.
main.py를 수정하지 말고, check.py에서 들어오는 입력 → 함수 호출 → 반환 → assert 실패 흐름을 따라 분석해줘.
실제로 재현한 사실과 추측을 따로 적고 관련 코드 줄을 제시해줘. 로그에 개인정보/토큰이 있으면 제거해줘.
```

**2. 최소 수정**

```text
확인된 원인만 main.py에서 최소한으로 수정해줘.
정상 결과와 출력 구조를 보존하고 check.py, solution.py, 의존성 및 다른 차시용 코드는 변경하지 마.
검사 무력화, 임시 예외 무시, 하드코딩으로 통과시키는 편법은 금지.
완료 조건: python check.py main 명령에서 정상과 실패/경계 조건 모두 PASS.
실행한 명령과 실제 결과를 기록하고 실행 불가 시 미검증이라고 밝혀줘.
```

**3. 검토**

```text
변경한 줄을 오류 원인에 연결하고 diff를 설명해줘.
정상 입력이 보존됐고 오류·경계 입력을 실제로 검증했는지 로그로 보여줘.
새로 추가한 미사용 코드나 다른 차시 기능이 없는지 확인해줘.
남은 한계와 실제로 수행하지 않은 검증을 분리해서 적어줘.
```

**왜 세 단계인가?** 원인 분석 없이 AI가 수정을 시작하면 증거가 사라질 수 있습니다. 수정 범위를 제한해 회귀 오류를 줄이고, 최종 검토에서 AI 주장을 실제 실행 기록과 대조합니다.
