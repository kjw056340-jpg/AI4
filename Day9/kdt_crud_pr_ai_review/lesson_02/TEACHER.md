# 강사용 운영 지침 — 2차시

## 핵심 정답 및 증상

- 시작 코드 결함: 없는 항목에 None을 그대로 반환해 200 null이 된다.
- 최소 수정 원리: 찾지 못하면 HTTPException(status_code=404)을 발생시킨다.
- 정상 보존 사례: 기존 /tasks/1 → 200; 미존재 /tasks/999 → 학생 200 null, 정답 404
- 수업 계획: 0–5 예측 → 5–15 해설 → 15–28 재현 → 28–40 AI 분석과 최소 수정 → 40–47 검증 → 47–50 제출.

## 질문과 답

1. 왜 시작 코드가 실패하나요? → 없는 항목에 None을 그대로 반환해 200 null이 된다.
2. 왜 테스트를 바꾸지 않아야 하나요? → 요구사항을 검사하는 기준을 유지하기 위해서입니다.
3. 단순 정적 분석만으로 충분한가요? → 실제 입력과 출력, 실패·수정 후 재실행이 필요합니다.

## 진행상의 주의

수업 이전 설치를 끝내며, 서버 또는 Git 변경 상태를 명확히 구분합니다. 정상 테스트가 처음 통과하고 버그 테스트만 실패하는지 관찰합니다. Codex의 검토는 보조 수단이며 정답의 근거는 실제 실행 결과입니다. 학생은 오류 원인, diff, 검사 결과를 제출합니다.

## 차시 범위 감사

`lesson_scope.json`은 강사용 검수 문서입니다. 선언된 경로와 실제 `check.py` 호출을 대조하고 모든 import와 함수가 이번 차시에서 쓰이는지 확인합니다. 다음 차시 기능을 넣지 않습니다.
