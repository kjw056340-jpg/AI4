# Day1~Day8 분석과 구현 선택

분석 대상은 저장소의 `Day1`, `Day2`, `Day3`, `Day4`, `Day6`, `Day7`, `Day8` 소스입니다.
`Day5` 폴더는 실제로 존재하지 않아 내용을 추정하지 않았습니다.
`Day1-Day8`은 결과물 폴더이며 원본 수업 범위와 구분합니다.

## 원본을 읽을 때의 주의점

- 학습용 초안·수정본·정답 파일이 함께 있으므로 모든 파일을 모범 구현으로 보지 않았습니다.
- `Day8/lesson_04_ai_test_cases/main.py`는 `amount > 10000`을 사용하지만 README의 규칙은 `10000 이상`입니다. 경계값 검사가 필요한 예입니다. 이번 작업에서 원본은 수정하지 않았습니다.
- `Day7/03/main.py`의 `as_completed` 결과를 요청 ID와 단순 zip하면 완료 순서와 요청 순서를 혼동할 수 있습니다. 방명록에는 이런 병렬 처리를 넣지 않았습니다.
- `Day4/day4-1`의 연속 대입은 첫 값을 덮어쓴 뒤 그 값을 다시 사용하므로 양끝 교환이 아닙니다. 방명록에는 교환 알고리즘이 필요하지 않습니다.
- `Day4/login.txt`는 방명록 구현에 필요한 소스가 아니므로 인증 정보로 사용하거나 결과물에 복사하지 않았습니다.

## 유지하는 기술과 최소한의 확장

외부 직접 의존성은 Day8과 같은 FastAPI 0.115.12, Pydantic 2.11.5, Uvicorn 0.34.2입니다.
검사 도구도 기존 httpx 0.28.1, pytest 8.3.5를 유지했습니다. 최신 버전을 의미하지 않으며,
하위 의존성을 모두 고정한 잠금 파일은 아닙니다. 버전 변경은 이번 범위에서 수행하지 않았습니다.

사용자가 지정한 내장 DB 요구에 따라 표준 라이브러리 `sqlite3`를 사용합니다.
HTML 기본 폼은 표준 `urllib.parse.parse_qs`, 사용자 글의 HTML 변환은 `html.escape`,
HTML 파일의 자리 채우기는 `string.Template`로 처리합니다.
경로·환경 변수·연결 정리는 `pathlib`, `os`, `contextlib`로 처리합니다.
이들은 Python에 포함되어 별도 설치가 없습니다. Jinja2, python-multipart, ORM은 추가하지 않았습니다.

## 요청이 처리되는 순서

1. 브라우저가 기본 HTML form으로 작성자·내용을 보냅니다.
2. 서버가 폼 형식·필드 개수와 길이를 확인합니다.
3. Pydantic이 공백을 제거하고 빈 값·초과 길이를 거절합니다.
4. SQLite 트랜잭션에서 총 개수를 확인한 뒤 매개변수 SQL로 저장합니다.
5. 성공 시 303으로 목록에 이동합니다. 이후 새로고침은 GET입니다.
6. SQL의 `ORDER BY id DESC LIMIT 20 OFFSET ...`으로 최신 글을 가져옵니다.
7. 반복문으로 글마다 HTML을 만들고 사용자 입력을 escape한 뒤 HTML 파일에 채웁니다.

정렬은 SQLite의 정수 기본키 순서를 활용합니다. 별도의 정렬·검색 알고리즘을 구현하지 않습니다.
화면 출력은 페이지의 글 개수에 비례하며 한 번에 최대 20개만 만듭니다.
OFFSET과 COUNT는 데이터가 커지면 비용이 늘지만 전체를 1,000개로 제한하므로 고급 페이지 기법을 도입하지 않았습니다.
`BEGIN IMMEDIATE`로 개수 확인과 저장을 묶어 동시에 두 요청이 와도 한도를 넘지 않게 합니다.

추가 패키지나 새로운 기능용 알고리즘을 도입할 필요가 생기면 구현 전에 사용자에게 묻습니다.
